# ITHomeAdKill — IT之家去广告 Xposed 模块

针对 IT之家 Android 版（包名 `com.ruanmei.ithome`）的 LSPosed 模块。

## 功能

- Miuix 设置主界面，支持总开关，所有净化规则可独立控制，跟随系统深浅色。
- 应用：可隐藏模块自身桌面图标，隐藏后可从 IT之家设置页顶部的“ITHomeAdKill”或 LSPosed 的模块设置入口打开并恢复，不影响 IT之家图标。IT之家内的入口不受净化总开关影响。
- 首页：关闭轮播，自动刷新可选关闭、1 分钟、5 分钟、10 分钟。
- 文章：关闭 AI 总结、文章打分、打赏与红包区域，不影响正文、评论支持/反对。
- 文章佣金广告：独立开关“关闭佣金广告”，隐藏文章商品广告卡、已识别的佣金跳转链接及底部广告声明。普通官网、商品参数和参考链接保留，未知推广结构不盲目拦截。
- 评论：可选“评论层级连接线”，覆盖文章评论区、独立评论列表及热门评论“展开”页面。按真实父子关系将完整子树放在一起，绘制共享竖干、圆角 L 形分支与末条收尾，去除子回复灰底。兄弟回复保留原顺序和原楼号，展开后的新增回复自动重新归位；关闭后恢复原顺序、背景与缩进。默认关闭，不增加折叠按钮，不改变点赞、反对、回复操作。
- 更多净化：信息流广告、置顶、明确标记的网页推广；广告开关也覆盖已识别的文章底部广告和首页悬浮营销入口。

原有净化选项默认开启；“关闭轮播”“关闭 AI 总结”“关闭文章打分”“关闭打赏与红包区域”“关闭佣金广告”和“评论层级连接线”默认关闭；自动刷新默认关闭。事件日历使用 IT之家官方“资讯列表设置 → 最新栏目显示事件卡片”控制，模块不再重复拦截。

自动刷新仅作用于**前台、有焦点、当前可见的资讯栏目**。进入文章、后台、其他页面、切换栏目或拖动交互时暂停或重新计时，不刷新预加载的其他栏目、不补跑后台错过的次数。刷新调用应用原有 listener，不额外拼接或访问新闻接口。

## 原理与兼容边界

本模块采用视图级拦截与文章模板的精确 CSS：

1. 精确匹配 `tv_small_tags` 的“广告”/“置顶”，按整卡判断，避免一张卡片中正常标题把广告角标的隐藏结果覆盖。
2. `ll_web` 容器本身不证明是推广。仅同时具有明确广告标记时隐藏，正常或未知网页卡片保留。
3. 首页轮播、文章原生评分、已识别广告入口限制在对应页面与资源结构；重绑前释放模块拥有的折叠，开关关闭时恢复宿主期望的布局状态。
4. 文章 AI 摘要只处理模板 `.ai-abstract`；HTML 评分只处理对应文章评分节点，打赏与红包只处理 `body > .reward` 完整区域。不做“AI”“广告”“打赏”等全文关键词过滤，不改支付逻辑。
5. 佣金广告仅在文章容器内处理模板的 `.card.main-site`、`.ad-tips` 及已证实的 `u.jd.com`、`union-click.jd.com`、`s.click.taobao.com` 佣金跳转入口，包含 Android 专用链接属性。不按“直达链接”或“京东”等文字泛化匹配，不屏蔽整个平台域名，不删除正文 DOM。

当前资源与实机适配基线为 **IT之家 9.55**。未知布局/不可读设置失败开放，不应据此推断已兼容后续所有版本。部分广告是否出现受服务端下发影响，不能把未遇到广告当作拦截命中证据。

## 使用步骤

1. 确认框架实现支持 **现代 Xposed API 102** 及 Remote 能力，再安装模块 APK。仅管理器显示“API 102”不足以证明所有现代接口可用。
2. 在 LSPosed 管理器中启用「IT之家去广告」，作用域仅勾选 IT之家。
3. 从桌面图标打开设置，连接到唯一可用的框架 service 后选择功能。未连接时不接受本地离线保存，避免 UI 与宿主读到两套设置。
4. 返回或强制停止后重开 IT之家。设置保存仅确认框架持久化，不代表宿主已经加载 Hook。

## 构建

用户安装包使用 R8 优化的 Release 变体，避免把未优化的多 DEX 调试包当日常版本发布：

```sh
./gradlew testDebugUnitTest lintRelease assembleRelease
```

产物位于 `app/build/outputs/apk/release/app-release.apk`。当前沿用既有 Debug 签名保持已安装版本的覆盖兼容，构建发布仍须使用原有 keystore；Release 在此表示关闭调试并启用代码/资源优化，不表示更换签名。Xposed 元数据入口的精确保留规则位于 `app/src/main/keepRules/`。

## 查看拦截日志

LSPosed 日志或 `adb logcat` 过滤 `ITHomeAdKill`。日志仅记录设置可读状态、选择器状态与刷新事件，不输出文章正文、账户数据或新闻请求。

```sh
adb logcat -s ITHomeAdKill:I
```

`settings=ready:N` 表示宿主读到完整设置版本；`unavailable` 表示未初始化、不兼容或不可读，此时不执行净化/刷新。`native-selector=...` 只表示发现结构，不能单凭它认定广告命中。

## 进阶排查（如果还有漏网广告）

1. 用 `adb shell uiautomator dump` 抓取广告所在页面，找到广告卡片特征
   （角标文字、卡片根 resource-id）
2. 在 `hook/HostRuntime.kt` 中补充有边界的页面/结构识别，并为纯规则补回归测试。
3. 用真实安装的模块与同一内容做开关 A/B，确认正常新闻、评论和复用恢复不受影响。

## 注意

- minSdk 26，需要完整的现代 API 102 实现。使用 `io.github.libxposed:api:102.0.0` 与官方 `service:102.0.0`；不保留旧 API 82 Hook 或 legacy 共享偏好回退。
- 设置只保存功能开关与刷新间隔等非敏感值。通过官方框架 RemotePreferences 共享，service AAR 自带官方 Provider，不自建 IPC、不手动修改文件权限。
- 兼容未知或不可读配置时不运行净化；首次使用应打开设置主界面。
- schema 1/2/3/4 完整配置迁移到 schema 5 时保留原开关、刷新间隔和配置身份，新增评论树开关默认关闭。schema 1 的旧日历项退役，打赏与红包默认关闭；schema 1/2/3 的佣金广告开关同样默认关闭。
- 从 legacy APK 跨到现代后端时，框架不保证两种偏好目录相同。仅导入应用私有目录内已由旧官方共享后端导出的、通过严格类型校验的配置；远端非空时始终以远端为准。未经导出不能保证保留旧设置，不读取可能过期的私有偏好猜测迁移。
- 旧版已退役的 `comment_thread_lines` 键仍不生效；新版评论树使用独立的 `comment_tree_lines` 键，不会因为旧键为真而自动开启。不同根组不混排；缺父、循环、重复等未知关系保留原样，不猜关系。
